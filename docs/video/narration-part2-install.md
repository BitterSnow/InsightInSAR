## 第二部分 软件安装

这一部分是全流程里最关键的环节。  
我们采用向导式安装，而不是让用户手工敲一长串命令。  
安装成功的关键，不在于步骤多，而在于顺序正确、文件齐全、路径关系正确。

请在同一个安装根目录下准备三项内容。  
第一项是 InSAR Desktop 主程序目录，双击其中的主程序即可运行桌面端。  
第二项是 InSAR WSL Deploy Wizard 部署向导目录，用于导入 WSL 环境并写入配置。  
第三项是 insar-wsl 镜像文件，通常名为 insar-wsl.tar，由构建机提前导出后随安装包一起交付。

这里有一个很容易被忽略但非常关键的点。  
如果缺少 insar-wsl 镜像文件，你可能还能打开桌面界面，但无法完成完整的 WSL 处理能力部署。  
也就是说，界面能开，不代表计算链路已经可用。  
为了避免后续能点按钮但任务跑不通的情况，建议安装阶段就把镜像文件准备完整。

准备好之后，请进入 InSAR WSL Deploy Wizard 目录，双击运行部署向导程序。  
向导通常会先检查 WSL 是否可用。  
检查通过后，你需要选择 insar-wsl 镜像的路径，再选择 WSL 导入目标目录。  
随后向导会自动执行导入，并检测 WSL 内的环境脚本，把安装根目录转换为 WSL 可访问的项目路径，写入运行配置文件。  
这一步的意义，是把系统运行参数固化下来，避免手工配置错误。  
配置会保存在安装目录以及本机应用数据目录中，主程序启动时会自动加载。

向导完成后，再进入 InSAR Desktop 目录，双击主程序启动。  
请注意这个先后顺序：先部署向导，再开主程序。  
如果反过来操作，常见结果是主程序能启动，但任务提交后在计算阶段失败。

再补充三个安装层面的高频注意点。  
第一，先确认 WSL2 已启用，这是基础前提。  
第二，确认三个安装要素在合理目录结构中，部署向导与主程序目录应与安装根目录保持文档约定的层级关系。  
第三，确认你确实执行过部署向导，并完成镜像导入，而不是只复制了文件夹。  
按这三个顺序排查，通常可以快速定位安装问题。

本系统还支持环境与代码分离。  
WSL 镜像主要承载 Ubuntu 以及 ISCE2 和 MintPy 运行环境，更新频率较低。  
业务代码放在 Windows 安装根目录下，由 WSL 通过挂载路径访问。  
因此日常若只更新后端脚本或 MintPy 相关代码，可以覆盖对应文件夹，无需重新导入镜像；只有环境大版本升级时才需要重新导出并导入新的镜像。
